# Asset migration and disposition contract

This module records how assets produced before the current directory blueprint were assigned, consolidated, or deleted. It records provenance and ownership; it does not change scientific status.

`asset-ledger.jsonl` is generated by `scripts/sync-asset-migration.mjs`. Each line represents an asset family or Experiment directory. `FINAL_RECEIPT.json` preserves original legacy-source digests, the seven Student Mission assignments, the exact cleanup contract, and the evidence boundary after old prose or cache paths are removed.

The preserved `cycles/*-LEGACY-IMPORT.md` paths are Bootstrap Import records for compatibility and provenance. Despite the historical `CY-*` filenames and the receipt's legacy `importCycle` field, they are not Student scientific Cycles or Handoffs and require no Mentor settlement. `ASSETS.yaml.bootstrap_imports` points to each record with its own URI + digest; deleted original inputs remain separate `source_refs + source_sha256`, so a digest never pretends to cover a different URI. The owning `create-ready` Student audits any imported scientific assertion in its first real Cycle.

Rules:

- preserve the original path and digest before any move;
- register valid legacy evidence in place rather than fabricating missing Run closure;
- assign working state to exactly one Track / Student Mission / Research Line lineage before migration;
- keep Dashboard projections and generated cache out of scientific evidence;
- never infer an active Chat from a create-ready Student workspace;
- never infer a prior Handoff or Mentor review from a Bootstrap Import;
- never treat relocation, consolidation, or cleanup as scientific promotion.

Run:

```bash
node scripts/sync-asset-migration.mjs
node scripts/sync-asset-migration.mjs --check
node scripts/rehome-legacy-assets.mjs --check
```
